# Contributing

Thanks for helping improve the SeatSpace library seat system.

1. Open an issue to describe a bug or proposed change when the scope is not already clear.
2. Create a branch for your work and keep changes focused.
3. Run the relevant service locally and describe the manual checks in your pull request.
4. Do not commit database files, Wi-Fi credentials, passwords, tokens, or personal data.
5. Open a pull request with a short summary, setup notes, and any limitations.

The project is a prototype. Coordinate changes to the sensor payload and SQLite schema with maintainers because the firmware, API, monitor, and reservation service share those interfaces.
